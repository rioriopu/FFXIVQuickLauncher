# ランタイムの確認と修復

設定の「ゲーム内機能」タブにある「ランタイムの確認・修復」から開きます。
起動時の警告に表示された系列（.NET 6・8・9）を選ぶと、Windows x64 の .NET Runtime と Desktop Runtime の導入状況を表示します。
別系列のランタイムが入っていても、選択した系列の代わりにはなりません。

「修復」を押したときだけ、Microsoft 公式の配布情報から同じ系列の最新パッチを調べ、Desktop Runtime のインストーラーを取得します。
Desktop Runtime には .NET Runtime も含まれます。
公開された SHA-512 と一致した場合だけインストーラーを開きます。
その画面の案内に従って導入または修復してください。自動的な無人インストールは行いません。
終了後は導入状況を再確認します。再起動が必要な場合はインストーラーの案内に従ってください。
.NET 6 は互換用であり、Microsoft のサポートは終了しています。

確認・取得・検証・終了の履歴は画面の直近20件と通常ログの `[RuntimeRepair]` に残ります。
取得中に確認画面を閉じると、取得を中止します。
取得済みのインストーラーは `%LOCALAPPDATA%\XIVLauncher\runtime-repair` に保存し、再利用時にも検証します。

Dalamud 専用のランタイムは、各データフォルダの `runtime` にあります。
こちらは配布情報に指定された版をゲーム起動前に自動確認します。
7.0.33 以降は取得・展開・検証を一時領域で完了してから追加し、旧版のフォルダは保持します。
同じ保存先への更新は順番に処理します。

7.0.34 では、7.0.33 で既存ファイルの上書きができず、更新や破損修復を繰り返し失敗する問題を修正しました。
本家と同じ公式ハッシュによる正常性確認を継続し、不一致・欠落・版の違いがある場合に取得します。
再取得した対象版の構成を入れ直すため、破損した構成内の不要ファイルも持ち越しません。
配置先も再検証し、途中で失敗した場合は入替前の内容へ戻します。
更新内容が同じファイルには触れず、変更が必要なファイルが使用中なら起動前の再試行に任せます。
正常な状態で次回起動した場合は再取得しません。

7.0.35 では、Dalamud 用ランタイムの本体・検証ハッシュと、アセットの一覧・本体をVPSへミラーしています。
取得はVPSを優先し、通信や検証に失敗した場合は公式へ切り替えます。
ランタイムは更新確認のたびに版・必要ファイル・保存済みハッシュを照合しますが、正常なら再ダウンロードしません。
アセットの一覧は毎回確認します。本体は新しい版・欠落・破損がある場合だけ取得します。
ミラーの一覧が手元に導入済みの版より古い場合は採用せず、公式へ照会します。

VPSの同期は `scripts/mirror-dalamud-dependencies.py` を使用します。
`--root` に静的公開先、必要なら `--public-base` に公開URLを指定してください。
公式ハッシュで検証できた内容だけを版別に公開し、一覧は最後に切り替えます。
取得や検証が失敗した場合は、既存の公開ファイルを残します。
同期間隔は配信先の定期実行設定に従います。現在のEstell配信先では30分ごとです。
利用者側の取得元・代替・検証の結果は通常ログの `[DDEPEND]`、`[DUPDATE]`、`[DASSET]` に残ります。

7.0.36では、Dalamud本体ZIPもVPSを優先し、失敗した場合は元の配布先へ切り替えます。
本文の転送が30秒止まった場合も取得先を切り替えます。
版別ZIPのSHA256、展開後の必要ファイル、DLLに埋め込まれた版を検証してから配置します。
取得や検証に失敗しても既存の配置は残します。同じ保存先への本体更新も順番に行います。
配布情報がHTTPエラーを返した場合もミラーを試し、自前トラックを取得できない場合は別トラックへ切り替えずエラーを表示します。

この画面の確認対象は Windows 側です。個別アプリが専用の保存先を使っている場合は、そのアプリ側の修復が必要なことがあります。
警告を出すアプリの所在が不明な場合、ランタイム不足とゲームのクラッシュが同じ原因とは限りません。
